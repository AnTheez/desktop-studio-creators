# Contributing

Thanks for helping make Desktop Studio customization easier and safer.

## Good contributions

- clarify a creator-facing contract;
- add a small, original, dependency-free example;
- improve validation and actionable error messages;
- propose a bounded property or permission with a clear user benefit;
- report a package that behaves differently between the editor and runtime.

## Pull request checklist

1. Keep examples offline and portable.
2. Do not add native executables, generated bundles, secrets, or copyrighted assets you
   cannot redistribute.
3. Update the matching schema and documentation together.
4. Run `npm test`.
5. Explain compatibility and security implications in the pull request.

Public format additions are proposals until the paid Desktop Studio runtime implements and
tests them. Reserved runtimes or permissions must not be described as available.
